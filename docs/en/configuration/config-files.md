# Configuration files

SpiderByte stores local, accountless configuration in TOML. The configuration selects a provider and model, controls the agent loop, and defines local policies; it never requires a hosted SpiderByte account.

The default directory is `~/.spiderbyte`. Set `SPIDERBYTE_HOME` to move it:

```sh
export SPIDERBYTE_HOME=/path/to/spiderbyte-home
```

The main file is `$SPIDERBYTE_HOME/config.toml`. Terminal preferences are stored separately in `$SPIDERBYTE_HOME/tui.toml`.

## A complete local/BYOK example

This example connects to an OpenAI-compatible local server without a credential. Replace the endpoint and model with a provider you control. Configure a BYOK secret through the CLI so it is encrypted separately from this file.

```toml
default_model = "local"
default_permission_mode = "manual"
default_plan_mode = false
telemetry = false

[providers.local]
type = "openai"
base_url = "http://127.0.0.1:11434/v1"

[models.local]
provider = "local"
model = "your-local-model"
max_context_size = 32768
capabilities = ["thinking", "tool_use"]

[thinking]
enabled = true
effort = "medium"
keep = "all"

[loop_control]
max_steps_per_turn = 100
max_attempts_per_step = 3
reserved_context_size = 4096

[[permission.rules]]
decision = "allow"
pattern = "Read"

[[permission.rules]]
decision = "deny"
pattern = "Bash(rm -rf*)"
```

The provider type selects a wire adapter. `base_url` may point at localhost, a self-hosted gateway, or a provider endpoint used with your own key. Use `SPIDERBYTE_SECRET_STORE_KEY` plus `spyderbyte configure --api-key-env <name>` for a persisted BYOK credential. SpiderByte does not ship managed credentials, hosted identity, billing, or usage entitlements.

## Top-level fields

| Field | Type | Description |
| --- | --- | --- |
| `default_model` | `string` | Alias from the `[models]` table used by new sessions. |
| `default_permission_mode` | `string` | `manual`, `auto`, or `yolo`. Manual is the safe default. |
| `default_plan_mode` | `boolean` | Starts new sessions in Plan mode when `true`. |
| `merge_all_available_skills` | `boolean` | Merges skills discovered from the configured skill roots. |
| `extra_skill_dirs` | `array<string>` | Additional skill directories. |
| `extra_agent_dirs` | `array<string>` | Additional agent-definition directories. |
| `telemetry` | `boolean` | Enables local event collection and any explicitly configured sink. Set `false` for a fully local run. |
| `providers` | table | Provider connection records. |
| `models` | table | Model aliases and capabilities. |
| `thinking` | table | Thinking defaults. |
| `loop_control` | table | Step, retry, and compaction limits. |
| `background` | table | Background task limits. |
| `tools` | table | Global tool switches. |
| `image` | table | Image resizing limits. |
| `permission` | table | Initial local policy rules. |
| `hooks` | array of tables | Local lifecycle hooks. |
| `identity` | table | Optional local agent identity metadata. |

Unknown fields are reported as configuration diagnostics. Run `spyderbyte doctor` after editing a file.

## Providers

Each `[providers.<name>]` record identifies one provider connection. Persisted credentials are represented by an opaque `secret_ref` generated by a local credential command; raw keys are not returned or stored in `config.toml`. The CLI does not silently obtain a hosted SpiderByte token.

| Field | Type | Description |
| --- | --- | --- |
| `type` | `string` | Wire/provider adapter, such as `openai`, `openai_responses`, `anthropic`, `google-genai`, `vertexai`, or an installed adapter. |
| `secret_ref` | `string` | Opaque reference to encrypted local credential material. Generate it through `spyderbyte configure` or a provider import command; do not invent it by hand. |
| `base_url` | `string` | Endpoint override, including a localhost or self-hosted endpoint. |
| `default_model` | `string` | Provider-level model default. |
| `env` | table of strings | Explicit fallback values for provider endpoint settings. Raw credentials in this table are legacy input and are migrated when the process starts. |
| `custom_headers` | table of strings | Headers sent to this provider. |
| `oauth` | table | An external provider token reference when an adapter explicitly supports it; this is not SpiderByte account login. |

For a BYOK provider, use the encrypted local credential flow or the process-local `SPIDERBYTE_MODEL_*` environment overlay. Do not put real keys in `config.toml`, examples, tests, or issue reports.

```toml
[providers.gateway]
type = "openai"
base_url = "https://api.example.test/v1"

[providers.gateway.env]
SPIDERBYTE_BASE_URL = "https://api.example.test/v1"
```

Endpoint values in the provider `env` table are preserved as local configuration. Legacy credential entries such as `OPENAI_API_KEY` are migrated into the encrypted store at startup; new credentials should use the CLI flow. A missing key or endpoint produces a stable provider-configuration error instead of a silent fallback.

## Models

Each `[models.<alias>]` record points to a provider and names the model sent on the wire.

| Field | Type | Description |
| --- | --- | --- |
| `provider` | `string` | Provider record name. |
| `model` | `string` | Upstream model identifier. |
| `max_context_size` | `integer` | Maximum context length. |
| `max_input_size` | `integer` | Optional input limit below the full context window. |
| `max_output_size` | `integer` | Optional output-token limit. |
| `capabilities` | `array<string>` | Explicit capabilities such as `thinking`, `image_in`, `video_in`, and `tool_use`. |
| `support_efforts` | `array<string>` | Supported thinking-effort values. |
| `default_effort` | `string` | Default thinking effort for this model. |
| `off_effort` | `string` | Wire value used to disable thinking when the provider requires one. |
| `base_url` | `string` | Per-model endpoint override. |
| `display_name` | `string` | Name displayed in the CLI. |
| `reasoning_key` | `string` | Optional non-standard reasoning field for OpenAI-compatible gateways. |
| `adaptive_thinking` | `boolean` | Enables or disables adaptive thinking for compatible adapters. |

Use `[models."<alias>".overrides]` for values that should survive catalog refreshes:

```toml
[models.local]
provider = "local"
model = "your-local-model"
max_context_size = 32768

[models.local.overrides]
max_output_size = 8192
display_name = "Local development model"
```

## Thinking and loop control

```toml
[thinking]
enabled = true
effort = "high"
keep = "all"

[loop_control]
max_steps_per_turn = 100
max_attempts_per_step = 3
reserved_context_size = 4096
```

`max_steps_per_turn = 0` or an omitted value means no explicit step limit. Retry limits apply only to transient provider failures. A policy denial, invalid request, missing credential, or unsupported capability is not retried.

## Local services, policies, and hooks

SpiderByte's supported web fetch path is local and uses the standard network stack with private-address protections. Hosted search, hosted fetch, managed workers, billing, and account services are outside this repository. If a deployment needs one of those capabilities, install and configure an explicitly separate extension; the Open Core packages do not import it.

Permission rules are evaluated locally before tool execution. Hooks are local processes and should be treated as code with the same privileges as SpiderByte.

```toml
[[hooks]]
event = "PreToolUse"
matcher = "Bash"
command = "node .spiderbyte/hooks/check-bash.mjs"
timeout = 5
```

## Migration and compatibility

The supported data directory is `.spiderbyte`. Legacy product directories and legacy engine flags are not part of the active runtime. If you are migrating an older checkout, export or copy only the configuration values you understand into a new file and run `spyderbyte doctor`; do not rely on an automatic hosted-account migration.
